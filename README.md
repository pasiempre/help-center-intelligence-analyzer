# Help Center Intelligence Analyzer

A data pipeline and Streamlit dashboard that scores customer support macros (canned agent replies) on effectiveness, groups similar macros by topic, and produces a list of macros to promote, rewrite, or archive.

> **Data note:** All data in this project is synthetic, generated by `src/data_generation.py`. Results demonstrate the method, not measured business impact.

---

## Project Overview

Support teams accumulate hundreds of macros over time but rarely measure which ones work. This project provides:

- **Effectiveness scoring** for each macro based on CSAT, handle time, and reopen rate
- **Topic clustering** (TF-IDF + KMeans) to find overlapping or redundant macros
- **Usage analysis** to surface effective but underused macros
- **Recommendations** for consolidation, deprecation, and promotion

## Data Model

1. **tickets** (fact table): one row per support ticket, with created/resolved timestamps, CSAT, handle time, contact driver, and reopen count.
2. **macros** (dimension table): one row per macro, with name, category, body, owner team, and active flag.
3. **macro_usage** (bridge table): which macros were used on which tickets.

## Effectiveness Index (0-100)

| Component | Weight | Rationale |
|-----------|--------|-----------|
| CSAT | 40% | Customer satisfaction is the primary outcome. |
| Handle time | 30% | Efficiency matters, but only if quality holds. Lower is better. |
| Reopen rate | 30% | A proxy for whether the macro actually resolved the issue. Lower is better. |

How a score is computed:
1. Aggregate each macro's average CSAT, handle time, and reopen rate.
2. Min-max normalize each component to 0-100 across all macros (handle time and reopen rate are reversed so lower is better).
3. Apply the weighted combination.
4. Macros with fewer than 5 uses get a neutral 50 per component, so low-usage noise doesn't dominate the rankings.

### Categories

- **High Impact (Popular):** top quartile effectiveness, high usage
- **Underused Gem:** top quartile effectiveness, low usage (candidates to promote)
- **Moderate / Below Average / Low Effectiveness:** candidates to review or rewrite
- **Unused / Low Usage:** fewer than 5 uses (candidates to archive)

## Topic Clustering

1. Combine macro name, category, and body text.
2. Clean the text and remove boilerplate phrases.
3. TF-IDF vectorization (500 features, 1-2 word n-grams).
4. KMeans with 12 clusters (`NUM_CLUSTERS` in `src/config.py`).
5. Label each cluster with its top terms.
6. Flag clusters with many low-scoring macros as consolidation candidates.

## Known Limitations

- **Synthetic data:** the generator controls the relationships the model finds. Real use would need a ticketing export (e.g. Zendesk).
- **Correlation, not causation:** macros used on easier tickets will look better. Agent skill and ticket difficulty are not controlled for.
- **Global normalization:** per-contact-driver baselines are computed in `calculate_baseline_metrics` but not yet used in scoring. Scores are min-max scaled across all macros, which is sensitive to outliers.
- **Cluster count is fixed:** 12 is a default, not tuned. Next step would be choosing k with silhouette scores.
- **Row-wise scoring:** `compute_macro_scores` uses `DataFrame.apply`; a vectorized version would be faster at scale.
- `predictive_model.py` is experimental and has no tests.
